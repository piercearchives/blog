## 🧭 1. Contexto da aula

Nesta etapa do projeto, o foco de UI Design será **mais enxuto**, pois o objetivo principal do curso é trabalhar o desenvolvimento em código.

Mesmo assim, a UI precisa ser planejada.

A interface deve estar alinhada aos **requisitos funcionais e não funcionais** levantados anteriormente, principalmente:

- Conforto durante a leitura;
    
- Boa hierarquia visual;
    
- Responsividade;
    
- Acessibilidade;
    
- Destaque para os posts;
    
- Organização das informações.
    

> 💡 **Ideia central:** UI não é apenas "deixar bonito". As decisões visuais precisam ajudar o usuário a utilizar e compreender a aplicação.

---

# 🌑 2. Escolha da interface Dark

Uma das primeiras decisões do projeto foi utilizar uma **interface dark**.

Existem dois motivos principais:

### ① Preferência estética

O desenvolvedor gosta de trabalhar com interfaces dark.

### ② Conforto para leitura

Um blog é uma aplicação com **alta carga textual**. O usuário pode passar bastante tempo lendo:

> 30 minutos → 40 minutos → ou até horas.

Por isso, o conforto visual se torna importante.

A interface dark também funciona como um diferencial em relação à grande quantidade de blogs que utilizam interfaces **light**.

### 🎯 Insight

Ao definir uma interface para um projeto, não pense apenas:

> "Qual estilo eu gosto?"

Pense também:

> **"Qual experiência esse estilo proporciona para o usuário?"**

---

# ⚪ 3. Interface com caráter neutro

Outra decisão importante foi criar uma interface **majoritariamente neutra**.

A ideia é simples:

> **A interface não deve competir com o conteúdo.**

Em um blog, o protagonista é o **post**.

Por isso, a composição utiliza principalmente elementos neutros, enquanto imagens e ilustrações recebem maior destaque.

### Exemplo conceitual

```text
┌──────────────────────────────────────┐
│                                      │
│          INTERFACE NEUTRA            │
│                                      │
│       ┌──────────────────┐           │
│       │                  │           │
│       │     IMAGEM       │ ← destaque│
│       │                  │           │
│       └──────────────────┘           │
│                                      │
│          Título do Post              │
│                                      │
│          Resumo do conteúdo          │
│                                      │
└──────────────────────────────────────┘
```

Se toda a interface tivesse muitas cores e elementos chamativos, eles poderiam **roubar a atenção do conteúdo**.

Por isso:

**Neutro → reduz distrações → conteúdo ganha destaque.**

---

# 🔎 4. Pesquisar antes de criar

Uma das ideias mais importantes desta aula:

> **Não tente reinventar a roda.**

Antes de construir uma interface, é interessante observar produtos que:

- já existem;
    
- possuem usuários;
    
- já foram testados;
    
- apresentam padrões de interface consolidados;
    
- pertencem ao mesmo segmento ou possuem problemas semelhantes.
    

Isso não significa copiar uma interface.

Significa **estudar soluções que já funcionam** e entender por que elas funcionam.

## Pingback

O Pingback também foi utilizado como referência para observar a composição de uma interface voltada para conteúdo.

A ideia principal extraída das referências foi:

> **O usuário deve conseguir identificar e consumir o conteúdo sem que a interface fique disputando atenção com ele.**

# 🎨 6. Paleta de cores

Uma das referências encontradas utilizava uma paleta extremamente simples, baseada essencialmente em:

- Roxo;
    
- Branco;
    
- Escala de cinza.
    

Mesmo utilizando poucas cores, a interface consegue criar uma composição visual agradável.

Isso demonstra um princípio importante:

> **Uma interface não precisa de muitas cores para ter personalidade.**

A hierarquia pode ser construída através de:

- contraste;
    
- escala de cinza;
    
- tamanho;
    
- peso tipográfico;
    
- espaçamento;
    
- posicionamento.
    

---

# 🖼️ 7. Imagens como ponto de atenção

Em uma interface neutra, imagens e ilustrações assumem um papel importante.

Como o restante da composição possui pouca interferência visual, uma imagem consegue naturalmente chamar atenção.

Por isso, no projeto:

**Interface neutra + imagem relevante = maior destaque para o post.**

Isso será especialmente importante porque as imagens dos posts posteriormente serão obtidas através da **API**.

# 🃏 8. Cards de posts

Outra referência importante apresentou os posts em formato de **cards**.

Um card pode reunir informações como:

```text
┌─────────────────────────────┐
│                             │
│          IMAGEM             │
│                             │
├─────────────────────────────┤
│ DATA                        │
│                             │
│ TÍTULO DO POST              │
│                             │
│ Pequeno resumo do conteúdo  │
│                             │
│ Read more →                 │
└─────────────────────────────┘
```

Esses elementos não foram escolhidos aleatoriamente.

Eles correspondem às informações levantadas anteriormente nos requisitos do projeto.

### Informações relevantes

- Data;
    
- Título;
    
- Imagem;
    
- Resumo;
    
- Acesso ao conteúdo completo.
    

Isso demonstra a conexão entre **levantamento de requisitos → UI Design**.

# 🔗 11. A conexão entre as etapas

Essa aula ajuda a visualizar que o projeto não começa diretamente no código.

Existe uma sequência:

```text
REQUISITOS
     ↓
PESQUISA
     ↓
REFERÊNCIAS
     ↓
MOODBOARD
     ↓
WIREFRAMES
     ↓
HIERARQUIA VISUAL
     ↓
UI DESIGN
     ↓
CÓDIGO
```

E existe uma conexão importante entre as aulas anteriores:

```text
Requisitos funcionais
        +
Requisitos não funcionais
        ↓
     UI Design
```

Por exemplo:

**Requisito:** blog precisa proporcionar boa experiência de leitura.

↓

**Decisão de UI:** interface neutra + boa hierarquia textual + contraste adequado.

# 🧠 12. O que você deve realmente aprender desta aula

Não é necessário memorizar quais imagens foram utilizadas como referência.

O mais importante é compreender o **processo de pesquisa**.

### Quando você começar um projeto:

**1. Não comece desenhando imediatamente.**

Primeiro entenda o problema.

**2. Pesquise interfaces semelhantes.**

Observe como outras pessoas resolveram problemas parecidos.

**3. Colete várias referências.**

Não dependa de uma única interface.

**4. Analise o motivo das escolhas.**

Não pense apenas:

> "Gostei dessa tela."

Pergunte:

> "Por que essa composição funciona?"

**5. Conecte referências aos requisitos.**

A referência precisa ajudar a resolver o problema do projeto.

---

# 💡 Insight principal

> **Referência não é inspiração estética apenas. É uma ferramenta de resolução de problemas.**

Você pesquisa para descobrir **como outros produtos resolveram problemas semelhantes**, e então utiliza esse conhecimento para construir sua própria solução.
